# 核心正确性第一轮优化设计

## 目标

在不引入第二轮执行上下文、不实现 ROS2 后端的前提下，修复目标解析、技能后置条件和运行时异常边界，使当前离线闭环在多实体场景和失败场景下保持确定、可解释、可观测。

## 设计决策

### 目标实体解析

- 优先按目标文本中出现的完整实体 ID 匹配容器和可抓取物。
- 未出现实体 ID 时，继续使用现有颜色和类型筛选能力。
- 筛选结果唯一时返回该实体；没有候选或存在多个候选时抛出 `PlanningError`。
- 不引入名称、别名或自然语言实体模型；这些属于后续能力扩展。

### 技能后置条件

- 将 `Skill.postconditions` 扩展为接收执行前世界、执行后世界、参数和 `SkillResult`。
- `ExecutionMonitor` 负责传递完整上下文。
- `PlaceSkill` 从执行前世界确定本次持有物，并验证该物体在执行后进入指定容器且机械臂已释放。
- 其它技能保持现有判断语义，只适配新接口。

### 运行时异常边界

- `AgentRuntime.run` 将目标解析、规划、调度、重规划和目标验证中的异常转换为失败 `RunReport`。
- 失败报告保留当前世界和已产生的执行轨迹，并写入 Memory。
- 一旦任务开始，所有受控失败都发出 `task_finished` 事件，避免观察端停留在运行态。
- 单步执行仍沿用已有重试与重规划策略；不改变重试次数语义。

## 测试范围

- 明确实体 ID、多候选歧义和原有单候选目标解析。
- 放置错误对象、容器已有其它物体、正确放置三类后置条件。
- 首次规划、调度、重规划和终态验证异常均返回失败报告并发出终态事件。
- 运行现有相关测试、全量测试、覆盖率和 CLI demo。
